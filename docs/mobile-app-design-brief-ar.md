# دليل دمشق: ملف تصميم تطبيق الموبايل

هذا الملف مخصص لتصميم تطبيق الموبايل الجديد فقط.
المصادر: الموقع الحي https://dalil-dimashq.com وملف `docs-api/dalil-openapi.yaml` (الإصدار `2026-10-13`)، بتاريخ 16 تشرين الأول 2026.
**البيئة الأساسية للتصميم والتطوير هي بيئة الاختبار (Staging)**، فكل ما هو موجود عليها يُعتبر متوفراً للتطبيق.
تحليل الموقع والـ API بالتفصيل موجود في الملف المرافق `website-and-api-analysis-ar.md`.

الملف مقسوم لقسمين مستقلين بنفس الفقرات (من 1 إلى 2.4): **الزوار** ثم **أصحاب المنشآت**. بعدها نصائح التصميم المشتركة.

# الجزء الأول: الزوار

## 0. الخلاصة السريعة

- الدليل العام (الأماكن، المناطق، الخدمات، الدوام، الصور، العروض، الأماكن المميّزة، الفعاليات) يُقرأ بالمفتاح العام **بدون تسجيل دخول**.
- الحجز بلا دفع ولا عربون، ويحتاج **تسجيل دخول**.
- **ناقص للزائر:** إرسال تقييم، وجدول ملف شخصي، والتحقق من الهاتف، والمفضلة (تحتاج API)، وواجهة اقتراحات منفصلة.
- **البيانات قليلة:** من أصل 920 مكاناً، 125 فيها رقم هاتف، و18 لها تقييم، و4 مميّزة، وعرضان فعّالان. صمّم على هذا الأساس.

## 1. ما هو موجود ومتوفر للزائر

### 1.1 الخلفية والاتصال

| البند | التفاصيل |
|---|---|
| نوع الخلفية | Supabase: واجهات PostgREST على `https://{project_ref}.supabase.co/rest/v1/...` ودوال `POST /rest/v1/rpc/<name>` |
| المصادقة على الطلبات | ترويسة `apikey` (مفتاح عام آمن في التطبيق) + `Authorization: Bearer <JWT>` بعد تسجيل الدخول |
| الصلاحيات | تُفرض في قاعدة البيانات (RLS والدوال) |
| تقسيم الصفحات | `limit` و`offset` أو ترويسة `Range` (حتى 1000 صف) |
| الفلاتر والترتيب | صيغة PostgREST: `select`، `order`، `status=eq.active`، `id=in.(a,b)` |
| الأخطاء | جسم `{code, message, details, hint}`. الاعتماد على `code` (مثل `42501` غير مسموح، `22023` مدخلات خاطئة، `54000` تجاوز الحد، `P0002` غير موجود) وليس على رمز HTTP |
| الصور | روابط عامة: `/storage/v1/object/public/place-photos/{path}`، مع صور مصغرة (`thumb_path`) |
| المنطقة الزمنية | `Asia/Damascus` |

### 1.2 بيانات الدليل (بدون تسجيل دخول)

| البيانات | الواجهة | أهم الحقول |
|---|---|---|
| الأماكن | `GET /rest/v1/places` | `id`، `type` (مطعم، وجبات سريعة، مقهى، فندق، بيت ضيافة، نُزُل، موتيل)، `status`، `name_ar`، `name_en`، `alt_name`، `area_id`، `address`، `lat`، `lon`، `phones[]`، `website`، `email`، `facebook`، `instagram`، `description_ar/en`، `cuisines[]`، `osm_hours`، `stars`، `tourism_class`، `verified_at` |
| المناطق | `GET /rest/v1/areas` | `name_ar`، `name_en`، `lat`، `lon` |
| الخدمات | `GET /rest/v1/amenities` و`place_amenities` | `code`، `name_ar`، `name_en`، `sort` |
| الدوام | `GET /rest/v1/place_hours` | `weekday` (0 = الأحد)، `opens`، `closes`، `season` (عادي / رمضان — رمضان لا يُعرض حالياً) |
| الصور | `GET /rest/v1/photos` | `storage_path`، `thumb_path`، `sort`، `is_cover`، `is_logo` |
| العروض | `GET /rest/v1/offers` | `title_ar/en`، `details_ar/en`، `starts_at`، `ends_at`، `photo_path` |
| الأماكن المميّزة الآن | `GET /rest/v1/featured_now` | `place_id`، `type` فقط |
| الفعاليات | `GET /rest/v1/events` | `title_ar/en`، `venue_name`، `starts_at`، `ends_at`، `status`، `poster_path`، `publish_from` |
| نتيجة التقييم | `GET /rest/v1/place_scores` | `rating_count`، `score` (لا توجد تقييمات زوار بعد؛ النجوم الظاهرة تصنيف فندق أو من الخريطة) |

### 1.3 الحسابات وتسجيل الدخول

- سياسة الخصوصية تصف دخول التطبيق برمز من 6 أرقام يصل بالبريد (OTP). الموقع يستخدم بريداً وكلمة سر (بوابة أصحاب المنشآت). الطريقة المعتمدة للتطبيق لسة سؤال مفتوح.
- **حذف الحساب:** `POST /functions/v1/delete-account` (إلزامي للمتاجر).
- الحجز يحتاج بريداً أو هاتفاً مؤكداً، وأن لا يكون المستخدم محظوراً، وأن لا يكون صاحب نفس المنشأة.

### 1.4 بلاغات الزوار

- بالـ API موجود: `POST change_requests` من نوع `report` (معلومة خاطئة، مكان مغلق…)، ويحتاج هاتفاً مؤكداً.
- **على الموقع ما في شاشة بلاغ للزائر** — الزائر بيروح لصفحة «تواصل معنا» بدلها. يعني الواجهة الخلفية جاهزة، بس تجربة الزائر بالموقع مو مبنية كبلاغ.

### 1.5 الحجز (جهة الزبون)

| الواجهة | الدور |
|---|---|
| `rpc/booking_availability` | معرفة التوفر (متاحة للجميع، حتى بدون دخول) |
| `rpc/create_booking` | إنشاء حجز (يحتاج دخول) |
| `rpc/cancel_booking` | إلغاء قبل الموعد |
| `GET booking_list` | حجوزاتي |
| `rpc/reply_fake_report` | الرد على بلاغ حجز وهمي |
| `GET fake_reports`، `GET booking_bans` | البلاغات والحظر الخاصة بالزبون |
| `GET notifications` + تعليم `read_at` | الإشعارات داخل التطبيق |
| `rpc/register_device` | تسجيل الجهاز لـ Push (android / ios) |

**قواعد مهمة للتصميم:**

- التوفر من `booking_availability`: `available`، `max_party`، `slot_minutes`، `horizon_days`، `last_date`، `minimum_booking_notice_minutes`، `response_hours`، `closed`، `responding_now`، `next_response_at`، `confirm_minutes`.
- إنشاء الحجز: الاسم (2–80)، الهاتف (`^\+?[0-9]{8,15}$`)، عدد الأشخاص، الموعد، مفتاح `p_client_key` لمنع التكرار، عرض اختياري، ملاحظة حتى 300 حرف. **بدون دفع.**
- حدود: 3 حجوزات مفتوحة، و4 طلبات في الساعة.
- حالات الزبون: `waiting`، `pending`، `confirmed`، `rejected`، `expired`، `cancelled_by_customer`، `cancelled_by_owner`، `attended`، `no_show`.
- الحظر: 15 يوماً، ثم 45، ثم دائم.
- إشعارات تهم الزائر: التأكيد، الرفض، انتهاء الصلاحية، الإلغاء من المنشأة، بلاغ عليك، قرار البلاغ، بدء الحظر، رفع الحظر.

### 1.6 نموذج التواصل

`POST https://dalil-dimashq.com/api/contact` — ترسل الرسالة إلى بريد الفريق ولا تحفظها في قاعدة البيانات. الحد حسب بصمة IP خلال آخر ساعة.

| الحقل | مطلوب | القواعد |
|---|---|---|
| `name` | نعم | 2–80 حرفاً |
| `contact` | نعم | بريد، أو هاتف (7–15 رقماً بعد التنظيف؛ الأرقام العربية مقبولة) |
| `type` | نعم | `general` · `add_facility` · `partnership` · `other` |
| `message` | نعم | 10–3000 حرف |
| `website` | لا | حقل وهمي للسبام: يُترك فارغاً |

نجاح: `{ok: true}`. أخطاء: `400 invalid` · `400 rejected` سبام · `413` · `429`.

### 1.7 روابط ومشاركة

- صورة مشاركة 1200×630: `/og/{id}-{hash}.jpg`.

## 2. النواقص (الزوار)

### 2.1 أ. مستعجل

**جدول الملف الشخصي `profiles`**

ما في جدول بروفايل. التسجيل والحجز يحتاجوا اسماً وهاتفاً. بدون الجدول شاشات الحساب والحجز ما بتنتهي.

**الإشعارات**

بدنا إشعارات بالإصدار الأول. النصوص منكتبها نحن هلق. لازم: قائمة، شارة غير المقروء، إذن الإشعارات. `register_device` موجودة؛ مرسِل الـ Push منضيفه نحن.

**البحث من الخادم**

الموقع يحمّل كل الأماكن ويفلتر بالمتصفح. على الموبايل هاد بطيء ومكلف عالبيانات، وما بينفع مع التوسع. **لازم واجهة بحث من الخادم من هلق** (نص، فئة، منطقة، ترتيب، صفحات) حتى شاشة البحث والنتائج تُصمَّم عليها، مو على تحميل القائمة كلها.

### 2.1 ب. غير مستعجل

| البند | شو نعمل هلق | ملاحظة |
|---|---|---|
| **المفضلة / الأماكن المحفوظة** | صمّم زر حفظ أو أخّرها | **بتحتاج API جديدة** (`favorites` + RLS). |
| **`featured_now` يعطي `place_id` و`type` فقط** | شريط «مميّز» بعد جلب بطاقة المكان | ما بترجع اسم ولا صورة ولا تاريخ. تجيب المكان من `places` وتحط شارة «مميّز». |
| **شروط الاستخدام** | أخّر الشاشة | مطلوبة للمتاجر لاحقاً. |
| **قنوات التواصل** | نصوص ثابتة مؤقتاً | لازم تصير **ديناميكية من لوحة التحكم**. |
| **رسائل أخطاء الخادم بالإنكليزي** | نترجمها نحن | |
| **دوام رمضان** | لا تعرضه | |
| **الأماكن القريبة / «مفتوح الآن»** | «مفتوح الآن» التطبيق يحسبها من `place_hours` | «بالقرب مني» API لاحقاً. |

**شرح `featured_now`:** الواجهة العامة بترجع بس أي مكان مميّز هلق ونوعه. التواريخ بجدول الإدارة `featured`. للتطبيق: `place_id` ← بطاقة من `places` ← شارة «مميّز». تحسين الترتيب والتواريخ مو مستعجل.

### 2.2 أسئلة لسة مفتوحة (الزوار)

1. هل **تقييمات الزوار** ضمن الإصدار الأول؟ نجوم فقط أم مراجعات نصية؟ وكيف تتم مراجعتها؟
2. هل نريد **آخر ما شاهدته** و**المشاركة** بالإصدار الأول؟ (المفضلة غير مستعجلة، وتحتاج API.)
3. هل يستطيع الزائر **الإبلاغ عن معلومة خاطئة أو مكان مغلق** من التطبيق؟
4. العروض: هل يمكن **الحجز مع عرض**؟ وهل نريد نافذة/بانر للعروض؟
5. **طريقة الدخول:** بالبريد وكلمة السر، أم برمز يصل بالبريد، أم الاثنتين؟
6. **حقول التسجيل** المعتمدة: الاسم الأول والأخير، الهاتف، سنة الميلاد، نوع الحساب، اللغة؟
7. كيف يتم **التحقق من رقم الهاتف**، وعبر أي مزوّد (SMS، واتساب)؟
8. هل يُسمح للتطبيق باستدعاء نفس `POST /api/contact`؟ وهل الاقتراحات تُرسل كرسالة تواصل؟
9. هل يوجد مشروع Firebase ومفتاح APNs للإشعارات؟
10. **مزوّد الخرائط** المعتمد للتطبيق.

### 2.3 ما يجب طلبه من العميل (للزوار / مشترك)

1. **ملف بيانات للاختبار** (أماكن مع صور وعروض وحجوزات) لبيئة الاختبار والتصميم.
2. **الهوية البصرية:** شعار Vector، أيقونة، شاشة بداية، ألوان، خطوط، زخرفة.
3. **صور بديلة لكل فئة** (مطعم، مقهى، فندق…).
4. **دليل الهوية** إن وُجد.
5. **النصوص:** شاشات ترحيبية، ووصف المتاجر بالعربية والإنكليزية. (نصوص الإشعارات منعنا مؤقتاً.)
6. **حساب تجريبي لزائر** مسجّل (لاختبار الحجز).
7. **مزوّد الخرائط**.
8. الموافقة على **تحليلات أو تقارير أعطال** (تحديث سياسة الخصوصية).

### 2.4 متطلبات تقنية (الزوار)

- **الخرائط:** خوادم OSM المجانية لا تكفي لتطبيق؛ نحتاج مزوّداً مدفوعاً. التحقق من التوفر في سوريا.
- **الروابط العميقة:** فتح صفحة المكان من الرابط داخل التطبيق.
- **المتاجر:** حذف الحساب، عمر 16+، مراجعة المحتوى إذا وُجدت تقييمات أو بلاغات.
- **توقيت دمشق** لكل الأوقات.
- اختبار الإشعارات والخرائط والدخول من شبكة سورية.

# الجزء الثاني: أصحاب المنشآت

## 0. الخلاصة السريعة

- بعد تسجيل الدخول: شاشات **منشأتي** منفصلة عن شاشات الزبون.
- من التطبيق يديرون: **الصور، العروض، الدوام، الحجوزات**.
- الربط بالمنشأة: رمز `DD-…` فوري، أو طلب مراجعة.
- تعديلات فورية للاشتراك المميّز (تواصل ووصف)؛ الاسم والنوع والعنوان تُراجَع.
- الميزات المميّزة (صور، غلاف، شعار، عروض) **للمشتركين فقط** — لغير المشترك تظهر بطاقة «تواصل معنا» بدل أدوات الرفع.
- **مستعجل:** محرر دوام أسبوعي يكتب `place_hours` (مو نص OSM).

---

## 1. ما هو موجود ومتوفر لصاحب المنشأة

### 1.1 الخلفية والاتصال

نفس اتصال الزائر (Supabase + `apikey` + JWT). كل عمليات صاحب المنشأة تحتاج مستخدماً مسجّلاً. الصلاحيات RLS: يرى منشآته فقط. الأخطاء بنفس رموز SQLSTATE. المنطقة الزمنية `Asia/Damascus`.

### 1.2 الحسابات وتسجيل الدخول

- على الموقع: بريد + كلمة سر (10 أحرف على الأقل، حروف وأرقام)، `display_name` في metadata، تأكيد إيميل، نسيت كلمة السر.
- حذف الحساب: نفس الدالة؛ ترفض حسابات فريق العمل.
- نوع الحساب (زائر / صاحب منشأة) وحقول التسجيل الكاملة لسة سؤال مفتوح.

### 1.3 أدوات صاحب المنشأة

| الميزة | الواجهة | قواعد مهمة للتصميم |
|---|---|---|
| ربط برمز سري `DD-…` | `rpc/claim_with_code` | بريد مؤكد؛ الرمز الغلط يُحسب محاولة |
| طلب ربط بدون رمز | `POST change_requests` (نوع `claim`) | الفريق يتصل بالمنشأة |
| منشآتي | `GET place_owners` | |
| تعديلات فورية (Premium) | `PATCH places` | هواتف، موقع، إيميل، فيسبوك، إنستغرام، وصف عربي/إنكليزي، `osm_hours` |
| تعديلات تُراجَع | `POST change_requests` (نوع `edit`) | الاسم، النوع، العنوان؛ وحد يومي. تصنيف الوزارة كذلك طلب مراجعة |
| طلب إغلاق المنشأة | `POST change_requests` (نوع `remove`) | |
| طلباتي | `GET change_requests` | `pending` / `approved` / `rejected` مع ملاحظة |
| الدوام المنظّم | `POST/DELETE place_hours` | للمحررين وPremium — **هذا المطلوب من محرر التطبيق** |
| الخدمات | `POST/DELETE place_amenities` | |
| الصور | Storage `place-photos` ثم `POST photos` | Premium. ضغط: أطول ضلع 1600px (400 للصغيرة)، WebP 0.82 ثم JPEG 0.85. مسارات: `{id}/{وقت}-{عشوائي}.webp` و`{id}/thumbs/…` و`{id}/offers/…` |
| الغلاف والشعار | `rpc/set_cover_photo` و`rpc/set_logo_photo` | |
| العروض | `POST/PATCH/DELETE offers` | النهاية بعد البداية، حد 60 يوماً |
| حالة الاشتراك | `GET subscriptions` | خطة `premium` مع بداية ونهاية |

### 1.4 الحجز (جهة صاحب المنشأة)

| الواجهة | الدور |
|---|---|
| `GET booking_list` | حجوزات المنشأة |
| `rpc/confirm_booking` | تأكيد |
| `rpc/reject_booking` | رفض (سبب اختياري) |
| `rpc/owner_cancel_booking` | إلغاء مؤكد (سبب **إلزامي**) |
| `rpc/mark_booking` | حضر / لم يحضر (من 30 دقيقة قبل الموعد حتى 3 أيام بعده) |
| `rpc/report_fake_booking` | بلاغ وهمي: مرة لكل حجز، و5 لكل منشأة خلال 30 يوماً |
| `booking_settings` + `rpc/set_booking_options` | استقبال الحجوزات، أقصى عدد، إشعار مسبق |
| `booking_response_hours` | ساعات الرد على الطلبات |
| `booking_blackouts` | فترات إغلاق (حد 60 يوماً) |
| `GET notifications` + `read_at` | إشعارات |
| `rpc/register_device` | Push |

إشعارات تهم صاحب المنشأة: حجز جديد، بدء مهلة الرد، إلغاء من الزبون، بلاغ جديد.

### 1.5 نموذج التواصل

نفس `POST /api/contact` (مثلاً طلب اشتراك Premium أو إضافة منشأة غير موجودة). نوع `add_facility` و`partnership` مناسبان لأصحاب المنشآت.

### 1.6 روابط

رابط المنشأة العامة نفسه يُفتح للزوار. من لوحة «منشأتي» يفيد زر «عرض كما يراه الزائر».

### 1.7 ميزات الموقع كمرجع لشاشات صاحب المنشأة

من `/owner/`: إنشاء حساب، دخول، نسيت كلمة السر، البحث عن المنشأة، الربط برمز أو طلب، تعديل المعلومات، رفع صور وغلاف وشعار، العروض (60 يوماً)، طلباتي. لغير المشترك المميّز: أدوات الصور والعروض مقفولة وبطاقة «تواصل معنا» للاشتراك.

### 1.8 الهوية البصرية

نفس هوية الزائر (داكن، Teal، ذهبي، النجمة الثمانية). شاشات صاحب المنشأة منفصلة بعد الدخول، مو نفس تبويبات الزبون.

### 1.9 سياسة الخصوصية

أذونات **الكاميرا والصور** لأصحاب المنشآت فقط (رفع صور المنشأة). باقي السياسة مشتركة.

## 2. النواقص (أصحاب المنشآت)

### 2.1 أ. مستعجل

**محرر الدوام**

الموقع فيه طريقتان وما بيتزامنوا:

1. **`places.osm_hours`** — نص حر مثل `Mo-Su 09:00-24:00`. هيك بيكتب صاحب المنشأة على الموقع.
2. **`place_hours`** — صفوف منظّمة (يوم، فتح، إغلاق). **هيدي** يلي الزوار بيشوفوها و«مفتوح الآن». الإدارة بتحفظها من لوحة التحكم.

يعني تعديل النص على الموقع ممكن ما يوصل لصفحة المكان. **بالتطبيق: محرر أسبوعي** (كل يوم فتح/إغلاق، أكثر من فترة باليوم إن لزم) يكتب على **`place_hours`**.

**جدول `profiles`**

نفس حاجة الزائر: اسم وهاتف لصاحب الحساب.

**الإشعارات**

صندوق حجوزات يحتاج تنبيه فوري (حجز جديد، مهلة الرد). نفس قائمة الإشعارات وإذن Push.

### 2.1 ب. غير مستعجل

| البند | شو نعمل هلق | ملاحظة |
|---|---|---|
| **شروط الاستخدام** | أخّر | |
| **قنوات التواصل** | ثابتة مؤقتاً | **ديناميكية من لوحة التحكم** لاحقاً. |
| **رسائل أخطاء الخادم بالإنكليزي** | نترجمها نحن (صفحة `/owner/` فيها ترجمة لبعضها) | |
| **دوام رمضان** | لا تعرضه بمحرر الدوام هلق | العمود `season = ramadan` موجود. |

### 2.2 أسئلة لسة مفتوحة (أصحاب المنشآت)

1. **طريقة الدخول:** بريد وكلمة سر، أم رمز بالبريد، أم الاثنتين؟ (نفس حساب الزائر أو مسار منفصل؟)
2. **حقول التسجيل** لصاحب المنشأة: هل نوع الحساب يُختار عند التسجيل أم بعد الربط بالمنشأة؟
3. كيف يتم **التحقق من رقم الهاتف** إن لزم؟
4. هل يُسمح للتطبيق باستدعاء `POST /api/contact` لطلب الاشتراك أو إضافة منشأة غير موجودة؟
5. هل يوجد Firebase / APNs؟
6. هل نعرض لصاحب المنشأة **تاريخ انتهاء الاشتراك المميّز** فقط، بدون سجل دفعات؟

### 2.3 ما يجب طلبه من العميل (لأصحاب المنشآت)

1. **ملف بيانات للاختبار** فيه منشأة مربوطة، وصور، وعروض، وحجوزات.
2. **حسابات تجريبية:** صاحب مجاني، وصاحب **Premium** مع منشأة مربوطة، ومكان تجريبي مع رمز `DD-`.
3. الهوية البصرية والخطوط (مشتركة مع الزوار).
4. الموافقة على التحليلات إن وُجدت.

### 2.4 متطلبات تقنية (أصحاب المنشآت)

- ضغط الصور ورفعها على الجهاز قبل الإرسال (نفس قواعد الموقع).
- إذن الكاميرا ومعرض الصور.
- إشعارات Push لصندوق الحجوزات.
- توقيت دمشق لأوقات الرد والحجوزات.

## 3. نصائح قبل البدء بتصميم الموبايل (وعند استخدام Figma Make)

### 3.1 التنقل وهيكلة المعلومات

- **شريط تبويبات الزائر:** استكشف · الخريطة · العروض · الحجوزات · الحساب.
- **صاحب المنشأة:** بعد الدخول، قسم «منشأتي» أو مفتاح تبديل الدور (شاشات غير شاشات الزبون).
- الواجهة الرئيسية في الموقع تملأ أول شاشة على الهاتف. في التطبيق: ترويسة مختصرة و**شريط بحث ثابت**، والعدّادات **شرائح فئات** أفقية.
- الفلاتر في **لوحة سفلية:** الفئة، أقل تقييم، المنطقة، فيه رقم هاتف، الترتيب.

### 3.2 القائمة والخريطة

- تبديل قائمة/خريطة، أو خريطة مع قائمة سفلية. تجميع العلامات مع 920+ مكان. معاينة عند الضغط.
- «بالقرب مني» يطلب إذن الموقع عند الضغط فقط.
- تمرير لا نهائي مع هياكل تحميل.
- صمّم لبيانات قليلة: صور بديلة، «لم يُقيّم بعد»، بلا أقسام فارغة.

### 3.3 صفحة المكان (الزائر)

- ترويسة غلاف قابلة للطي: شعار، الاسمان، النوع، المنطقة، شارة «مميّز».
- شريط إجراءات: اتصل، اتجاهات، مشاركة، حفظ (لاحقاً)، احجز إن كان الحجز مفعّلاً. نسخ الرقم بضغط مطوّل.
- الأقسام: عروض → صور → نظرة عامة → خدمات (أيقونات) → موقع → دوام (مطوي + «مفتوح الآن») → تواصل.
- «اكتمال المعلومات X من 6» أنفع في لوحة صاحب المنشأة.
- وضّح مصدر النجوم. لا قوائم مراجعات قبل تأكيد التقييمات.

### 3.4 اللغتان والاتجاه

- العربية RTL أساس، مع نسخة إنكليزية. اعكس الأسهم والأشرطة.
- الأسماء قد تكون بلغة واحدة أو اثنتين؛ صمّم للأسماء الطويلة.
- حدّد شكل الأرقام وصيغ التاريخ (أشهر شامية مثل «تشرين الأول»).
- تغيير اللغة في الإعدادات والترحيب، مو بالترويسة.

### 3.5 العروض والأماكن المميّزة

- تبويب عروض: انتهاء أو عدّاد، رابط للمكان، زر حجز مع العرض إن انحسم.
- المميّز: شريط أفقي أعلى «استكشف» مع وسم «مميّز / إعلان».
- بانر أو قصص بدل نافذة منبثقة.

### 3.6 مسار الحجز

**الزائر:** منتقي تاريخ حسب الأيام المتاحة، مواعيد `slot_minutes`، عدد أشخاص حتى `max_party`، اسم وهاتف من الملف، ملاحظة 300 حرف، «يرد عادةً قبل…»، شاشات الحالات التسع + حد أقصى + حظر + الرد على بلاغ وهمي.

**صاحب المنشأة:** تأكيد، رفض (سبب اختياري)، إلغاء (سبب إلزامي)، حضر/لم يحضر، إبلاغ وهمي. إعدادات: استقبال، أقصى عدد، إشعار مسبق، ساعات الرد، فترات إغلاق.

### 3.7 الحسابات وأدوات أصحاب المنشآت

- **الزائر:** بريد ثم رمز 6 أرقام (أو كلمة سر حسب القرار)، ملف شخصي، عمر 16+، حذف الحساب.
- **صاحب المنشأة:** اربط منشأتك (بحث → `DD-` أو طلب) → لوحة منشأتي (فوري مقابل مراجعة) → إن ما عنده اشتراك مميّز: بطاقة «تواصل معنا» بدل الصور/العروض → محرر دوام أسبوعي → صور/عروض إن كان مشتركاً → طلباتي.
- تواصل معنا: شرائح النوع + واتساب/إيميل (قيم مؤقتة إلى أن تصير من لوحة التحكم).

### 3.8 الحالات

لكل شاشة: تحميل، فراغ، خطأ (عربي)، رفض إذن (موقع / كاميرا / إشعارات)، ميزة معطّلة (حجز أو اشتراك مميّز).

### 3.9 نصائح لـ Figma Make

- بيانات حقيقية: `places` مع صور وبدونها، `offers`، `place_hours`، `amenities`، `PlaceType`، `BookingStatus`.
- مؤجّل: مفضلة (تحتاج API)، دوام رمضان، Light، مراجعات إن ما انحسمت.
- شاشات RTL وLTR، ونسخ: مع/بدون صورة، مفتوح/مغلق، مميّز، صاحب مجاني / مشترك مميّز.
- هوية الموقع: Teal داكن، فحمي، ذهبي، النجمة الثمانية، الزخرفة.
- ابدأ بمسار الزائر (استكشف ← المكان ← اتصل/اتجاهات) ثم الحجز ثم صاحب المنشأة. التقييمات لآخر شيء.
